# 분석 결과 기반 앱 제작 흐름

## 목적
APK/DEX 정적 분석 결과를 바탕으로 사용자가 자연어로 새 Android 앱 제작 또는 기능 개선을 요청할 수 있게 한다.

## 현재 구현 경계
- Android 제작 화면은 `ProjectBuilderScreen(activity, settings, referenceName, referenceEvidence, onSettings)` 인자를 받는다.
- `referenceName`과 `referenceEvidence`는 Study 단계에 전달되고, Build/Refine 프롬프트에도 포함된다.
- 사용자의 새 기능 요청은 참고자료 분석 근거와 별도 입력으로 취급한다.
- 생성된 프로젝트는 경로, 중복, 파일 수, 크기 및 Android 프로젝트 필수 구조를 검사한 뒤 앱 내부 저장소에 저장된다.
- Study/Build/Check/Refine는 AI 요청과 소스 검사 단계다. 실제 Gradle 빌드, APK 설치, 앱 실행 성공을 의미하지 않는다.
- 원본 APK를 실행하거나 원본 코드·이미지를 복사하지 않는 독립 제작을 기본으로 한다.

## 다음 연결 작업
분석 결과 화면의 실제 Compose 진입점에서 선택된 파일명과 분석 요약을 보존하고, "분석 결과로 앱 만들기" 액션을 제공해야 한다. 액션은 위 ProjectBuilderScreen에 해당 값을 그대로 전달해야 한다. 분석 화면의 파일/결과 상태를 재생성하거나 네트워크로 자동 업로드하지 않는다.

## 개인정보
APK/DEX와 분석 요약은 기기 내 보관을 기본으로 한다. 외부 AI 제공자를 사용할 때에는 전송될 분석 요약과 제공자를 사용자에게 알리고 사용자의 선택 후에만 요청한다. API 키를 로그나 프로젝트 소스에 기록하지 않는다.

## 검증 기준
- 분석 결과 화면에서 액션을 통해 제작 화면이 열리고 선택한 APK 이름과 분석 요약이 전달되는지 확인
- 사용자의 요청이 분석 근거와 별도 필드로 전달되는지 확인
- 생성된 프로젝트의 구조 검사 성공/실패 처리 확인
- Gradle 빌드와 에뮬레이터/실기기 실행은 각각 실제 수행 후에만 완료로 표시
